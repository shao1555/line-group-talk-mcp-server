# ADR 0014: D1 の読み取り行数を節約する

- 日付: 2026-11-01
- 状態: 採用

## 背景

索引化中に D1 Free の日次読み取り上限に到達し、ログイン開始を含む DB アクセスが失敗した。料金予約のたびに月全体と当日の監査記録を SUM しており、件数増加に対して累積読み取りが二次的に増えていた。ユーザーが Workers Paid へ切り替えたうえで、読み取りも削減する。

## 決定

- 詳細の `ai_usage` は監査記録として維持する。`ai_usage_totals` に月別の費用・日別かつ処理種別の利用量を保持し、主キーで判定する。初回は既存記録から移行する。
- 予約の条件付き INSERT と集計値の更新を同じ D1 バッチで実行し、並行予約でも上限を守る。予約が拒否された場合は監査行も集計値も増やさない。
- 実績反映は監査行の旧額との差分を使い、月・日・監査行を同じバッチで更新する。同じ実績を再反映しても二重に減額・加算しない。失敗時の予約額保持とユーザー別24時間の制御は維持する。
- ユーザー別24時間は `(owner_user_id, created_at)` のインデックスで絞った当人の記録だけを集計する。月間・全ユーザーの履歴はモデル呼び出しのホットパスで走査しない。
- `messages.knowledge_registered` と未登録分の部分インデックスを使い、定期処理が全メッセージを確認し直さないようにする。メッセージと索引化ジョブを同一バッチで作成する箇所では登録済み状態も保存する。登録の取りこぼしは未登録分だけから補完する。
- 配送対象は `max(next_attempt_at, queued_at + 10分, lease_until)` の式インデックスで選択する。完了分・将来の再試行・処理中の行を毎分走査しない。毎分100件・最大5件同時処理は維持する。
- 現在の参加確認には履歴の件数・期間集計を不要とする呼び出しを設ける。一覧に件数が必要な場合のみ集計し、未取消の会話メッセージ用の部分インデックスを使う。
- リリースの切り替わりに旧版が記録した利用額は、稼働中の旧リクエストの終了後に `scripts/rebuild-ai-usage-totals.sql` で再照合する。将来ロールバックや監査記録の直接修正を行う場合も、集計値を再照合する。
- DB の無料枠超過は参加確認エラーと区別し、診断コードを返す。ログにはパスと秘密情報を除いた技術的な原因を残す。

## 検証

全体・日次・ユーザー別の並行予約、実績の二重反映防止、定期投入の件数・期限・処理中の除外、未登録ジョブの補完を既存テストで検証する。本番の旧集計と主キー照会の `rows_read` を比較した。料金判定の2集計は5,032行から2行に減少し、金額・利用量が一致した。MCP の件数・期間集計は一覧ツールを呼ぶ場合だけ実行する。
