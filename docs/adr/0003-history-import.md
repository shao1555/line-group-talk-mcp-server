# ADR 0003: 過去ログは書き出しを優先して取り込む

- 日付: 2026-11-01
- 状態: 採用・テキスト取り込み実装済み

## 背景

Messaging API は、bot 参加前の履歴を一括取得する手段を提供しない。ユーザーは既存の会話もナレッジに取り込みたい。

## 決定

- LINE アプリのテキスト書き出しを優先し、Computer Use で書き出し操作を支援する。
- 書き出しで不足する場合、アプリで閲覧できる範囲をスクロール・コピーなどで補完する。
- 取得元、取得方法、対象期間、元データ位置、重複候補を保持し、全履歴取得を保証しない。
- 表示名と Webhook のユーザーID、書き出し発言と Webhook 発言は根拠なく同一と断定しない。
- 原本やインポート用ファイルは Git に含めない。

## 結果

画面を大量に読み取る時間とトークン消費を抑えられる。端末にない履歴は取得できない。
管理画面から日本語 LINE 書き出し（UTF-8、2MB・20,000発言まで）をアップロードする。本人と bot が現在参加しているトークから取り込み先を選び、件数・期間・書き出し名を確認して取り込む。各リクエストで参加確認・セッション・同一 Origin・CSRF を検証する。画像・スタンプなどの単独プレースホルダーとシステム通知は除外する。日付と時刻は JST として扱い、複数行の引用も維持する。

原本は非公開 R2 の `history-imports/<conversation>/<id>.txt` に保存し、D1 の `history_imports` にアップロード者・ファイル名・ハッシュ・進捗を記録する。発言に原本ID・行番号・表示名を付け、`user_id` は NULL とする。原本のダウンロード API は公開しない。

取り込みは100発言ごとのトランザクションに分け、ブラウザーから続行する。同じファイルの再アップロードで続きから再開できる。発言IDはトークID・日時・表示名・本文・同一内容の出現順のハッシュとし、重なる書き出しの同一発言は重複保存しない。同一分内の同内容の複数発言は維持する。ただし書き出しに本来のメッセージIDがないため、表示名変更・途中で切れた同内容の発言・Webhook の発言との照合は厳密にできない。Webhook の送信取消もインポート発言へ自動対応付けしない。

取り込んだ発言は既存の `knowledge_jobs` に登録し、定期処理が既存キューへ送る。埋め込みには表示名も含める。既存の月額・日次予算とトーク単位の検索制限を維持する。会話全体の要約や人物対応表は後続で実装する。
