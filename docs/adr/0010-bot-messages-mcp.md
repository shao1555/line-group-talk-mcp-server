# ADR 0010: bot の回答を発言者を区別して MCP に公開する

- 日付: 2026-11-01
- 状態: 採用

## 背景

MCP の履歴は人間の発言だけを返していたため、買い物リストなど bot が提案した内容を確認できなかった。回答は `bot_replies` に保存されているが、履歴取得と意味検索の対象ではなかった。

## 決定

- 送信成功した回答を `messages` にも保存し、`sender_role = 'bot'`・表示名 `bot`・質問ID `reply_to_message_id` を付ける。人間の発言は `sender_role = 'user'` とする。bot の LINE ユーザーIDは推測せず NULL とする。
- メッセージIDは LINE の送信結果の ID を使い、過去分で未取得の場合は `bot-reply:<質問ID>` を使う。送信日時は質問の `replied_at` を使い、取得できない過去分のみ回答作成時刻で補う。
- `get_recent_messages` は質問と回答を時系列に混在させ、bot 回答は全文を返す。`search_knowledge` は bot 回答も意味検索し、発言者・返信先を返す。bot の提案・回答は人間の決定・同意を意味しないとツール説明にも明記する。
- 既存の保存済み・送信済み回答を移行し、索引化ジョブを作成する。今後の通常回答と ping / pong も記録する。送信失敗・生成中・未送信の回答は公開しない。
- 保存に失敗しても送信済み回答を再送対象に戻さず、定期処理で補完する。移行済み bot 回答の索引化は大きな履歴アップロードの後ろに滞留しないよう送信する。既存の予算とキューを使う。
- 質問や根拠の送信取消で元の回答を無効化するときは、コピーした bot 発言・抽出文・チャンクも同一トランザクションで無効化し、Vectorize の削除を予約する。読み取り時の取消フィルターにより索引の削除完了を待たず非表示にする。bot 自体の取消が保存済みの場合も再作成しない。
- bot の新しい回答生成では、人間の発言を事実の根拠とし、bot 自身の提案を根拠に繰り返し学習する流れを避ける。明示的な返信による対話コンテキストは維持する。外部 MCP は bot 回答を含み、既存 HTTP 検索と bot 内部の検索は従来の対象を維持する。
- アクセスできるトークの検証は変更しない。別トークの回答は返さない。書き出し履歴の表示名だけから bot と断定しない。

## 検証

MCP 履歴の発言順・全文・役割・返信先、意味検索と期間拡張、別トークの拒否、送信済み限定、取消時のコピーとキャッシュの削除、保存失敗の補完、内部根拠からの bot 発言除外をテストする。
