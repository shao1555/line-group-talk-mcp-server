# ADR 0017: GLM-5.3-Flash と1対1の回答ハーネス

- 日付: 2026-11-01
- 状態: 採用（ADR 0011のモデル選定とADR 0016の資料配分・終了制御を更新）

## 背景

実際の会話を使った3モデル比較で GLM-5.3-Flash が予定/実績・別年の記録を最もよく区別した。一方、モデルIDの交換だけでは最終ラウンドでも検索を要求し、回数上限で失敗した。検索候補の前後にある温泉の案内が資料枠から落ちる問題もあった。

## 決定

- 1対1は `@cf/zai-org/glm-5.3-flash`、reasoning_effort=low、max_completion_tokens=4096を採用する。グループ回答・OCR・画像理解のモデルは変更しない。
- `direct-model.ts` にモデルID・入力/出力/キャッシュ料金・推論設定をまとめる。GLMは100万トークンあたり入力$0.15、出力$0.50、キャッシュ入力$0.03。QwenとOSSも比較/ロールバック用に保持する。
- 費用はプロンプトのUTF-8バイト数と出力上限から保守的に予約し、既存のD1原子的な予算判定を通す。正常時に実測トークンで精算する。思考トークンはcompletion_tokensに含まれるため二重加算しない。欠落/不正な利用量では予約を維持し、不正なキャッシュ件数は割引に使わない。$0.5/直近24時間、$0.4警告、アプリ全体の上限は維持する。
- 計画フェーズはツールを含むJSON、最終フェーズは回答のみのプロンプトとJSON schemaに切り替える。最大3推論・4ツール。残り枠を超えるツール要求は残り分だけ実行し、次は回答へ移る。最終回答にツール要求や生のJSONをLINEへ流さない。
- 1対1の生成期限は45秒、1推論は最大25秒かつ残り時間内。検索済みで残り20秒未満なら回答専用に移る。送信前の参加再確認にも生成期限+5秒までの共通AbortSignalを渡し、LINEの返信処理の時間を残す。グループの24秒は維持する。
- 資料は最大160候補のプールに保持し、重複を除く。プロンプトには最大12KB・根拠総数80以内で選択する。ヒットに55%、残りを前後発言に配分する。長文は本文を縮め、1件が大きくても後続候補を落とさない。新しい検索結果のために周辺候補を退避できる。
- 「今年」「去年」や明示された年がある場合、その年の投稿・本文にその年の明記日付がある資料を優先する。絞り込みではなく優先順位なので、前年に予約した翌年の予定も扱える。前後発言では短い相づちやURLだけの投稿より説明文を優先し、トーク/検索窓間で均等に選ぶ。
- 最初の本人の質問文による検索は全期間。モデルの発言期間フィルターにはdate_basis=message_timeを要求し、言い換え・後続検索で扱う。質問の出来事の年を発言期間と混同しても、元の全期間候補を失わない。
- 再利用するプロンプト・型/価格・資料配分・応答検証を分離し、比較のためだけに本番の挙動を複製しない。`eval:direct` は既定でdry-run、ライブ実行は明示し、試験の費用上限・応答時間・使用量・回答・補助チェックを記録する。個人のデータは管理対象外のdata/にのみ保存する。

LINE本文では段落の空行と1項目1行の箇条書きを指示する。改行なしの長文が返った場合は、送信前に日本語の文末で段落を補う。すでにある改行、URLのみの行、コードは保持し、文字列の `\n` を一括置換しない。JSON復号後の改行を、そのまま本文と保存履歴に残す。

最終応答のwire形式はv2として、answerを段落/箇条書きの文字列配列にする（最低2・最大8要素）。サーバー側で全要素を空行で連結し、内部では従来の文字列として保存・送信する。計画段階の記録回答が単一段落の場合や、旧文字列形式の回答は下書きとして最終推論へ送り直し、導入文だけを完了扱いしない。finish_reason=lengthは不完全な生成として拒否する。推論ログには本文を出さず、文字数と要素数を残す。

## 検証

単体/Workerテストで状態機械の上限、最終回答の型、権限/取消、料金計算と予算、長文・複数検索・前後会話・対象年の配分を確認する。ライブ試験では架空の5ケースと、既存の私有再現データの大会/旅行を確認する。LINEへの試験メッセージ送信は行わない。
