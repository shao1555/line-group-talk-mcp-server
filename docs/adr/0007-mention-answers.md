# ADR 0007: bot へのメンションにグループ内の根拠から回答する

- 日付: 2026-11-01
- 状態: 採用

## 決定

- LINE の `mention.mentionees[].type = user` かつ `isSelf = true`、または同じ会話の bot の回答への引用リプライを、bot への質問として扱う。
- 返信 API の `sentMessages[].id` を `bot_replies.line_message_id` に記録し、受信した `quotedMessageId` と照合する。以前の返信IDは遡って取得できないため、対応前の bot の回答へのリプライはメンションも必要。受信の引用先IDは `messages.quoted_message_id` に記録し、quote token は永続化しない。
- bot の回答へのリプライに他人（`type=user` かつ `isSelf` が true 以外）へのメンションがある場合は返答しない。bot と他人の両方がメンションされた場合も、この抑止を優先する。
- 他人の発言への引用リプライに bot がメンションされた場合、同じ会話・取消されていない引用先を D1 から直接読み、優先した根拠として渡す。解析済み添付の抽出文にも対応する。bot の過去回答は対話文脈として区別し、独立した事実の根拠にはしない。
- JavaScript の UTF-16 インデックスでメンション部分を除去する。通常発言・他人へのメンションには自動回答しない。
- 受信元会話IDをサーバーが固定し、直近20件の発言を D1 から取得する。索引の反映待ちや短い返答の意味検索漏れを防ぐ。質問自身・bot 宛ての質問・取消済み発言は根拠から除外する。
- 同じ会話のナレッジを最大5件検索し、上位3発言の前後2分の会話も補う。直近の会話と過去の資料に別々の文字数枠を割り当て、長い OCR に直近の返答が押し出されないようにする。
- 根拠が不足する場合、モデルは `search_history` を1回だけ呼び、検索語・任意のキーワード・発言日時の範囲を選べる。会話IDはモデルから受け取らない。日付は JST の開始日以上・終了日未満で検証し、Vectorize の数値メタデータ `sent_at` と D1 の両方で確認する。
- 通常の回答は日本語の文章をそのまま返し、追加検索が必要なときだけ `{"action":"search","search":{...}}` を返させる。検索引数を検証してサーバーが実行し、2回目は通常の文章で回答する。JSON のコードフェンスにも対応する。
- 通常の function calling が検索の宣言だけで終わるケースがあったため上記の明示的な検索要求を使う。回答全体を包む JSON モードは短文化後も途中で切れ、約15秒の応答になったため廃止した。変更案を同じ実データで再実行したところ、通常回答は約3.3秒・推論1回、過去検索を含む質問は約4.6秒・推論2回だった。これらは単発計測で応答時間の保証ではない。
- 受信値は実行時に検証する。旧方式で返り得た JSON 文字列・デコード済みオブジェクトも安全に読み取り、検索条件などの内部出力を回答として流さない。
- JSON が途中で切れるなど判断形式が壊れた場合は、残りの1回を JSON モードなしの回答生成に使う。追加検索したとは伝えず、提供済みの記録と一般知識から回答する。2回目も壊れていれば固定エラー文にし、未完の JSON や検索引数は送信しない。モデル呼び出しの上限は合計2回のまま。失敗の種類のみログに残し、原文やモデル出力は記録しない。
- 「去年」は質問日時から解釈する。ただし出来事の日時と発言日時は異なるため、過去の出来事だからと発言期間を必ず絞らない。期間検索が空なら同じ埋め込みで全期間へ広げ、人名等は D1 の文字列検索でも補う。発言日時だけを出来事の日付と断定しない。
- 検索根拠を最大5000文字、質問を2000文字、回答を512トークンに制限し、Mistral Small 3.1 で日本語の短い回答を作る。
- 通常の回答本文は200字以内・具体例は最大5個を指示し、長い手順や一覧は要求された場合に限る。具体的な材料の質問で JSON 出力が512トークンまで伸びて切れ、再生成を含め約14秒になったため。実データの同一質問で、短文化により約4秒・推論1回になったことを確認した（単発計測であり応答時間の保証ではない）。検索準備と各推論の所要時間・出力トークン数を、本文を含めずログに残す。
- チャットの記録を優先し、一般的な説明・おすすめ・記録にない補足は同じモデルの一般知識で具体化する。Web 検索や別モデルへのフォールバックは追加しない。会話の根拠が0件でも一般知識による回答を許可する。
- 記録由来の事実と一般的な提案を区別し、一般知識には資料番号を付けない。個人の行動・日付・好みなどグループ固有の事実は創作せず、過去検索でも見つからなければ不明と答える。現在の価格など未確認の情報を断定しない。
- 会話全体の要約や別グループの検索は行わない。資料内の指示は信頼しない。
- 回答には資料番号を付け、発言IDの一覧を D1 の `bot_replies` に保持する。bot 自身の回答生成では、返答履歴を人間の発言による根拠に混ぜない。外部 MCP への返答履歴の公開は [ADR 0010](0010-bot-messages-mcp.md) に従い、bot 発言として区別する。
- 送信直前に質問と根拠の取消状態を確認し、取消済み内容を回答しない。取消後は保存済み回答の該当本文も無効化する。
- 月予算は解析と共有し、日次既定100回の回答モデル呼び出しまで。1質問につき最大2回（検索判断と最終回答）。予算超過時はモデルを呼ばず固定文で通知する。
- Webhook は記録後に応答し、回答処理を `ctx.waitUntil` で継続する。reply token は永続化せず、返信が期限内に終わるようモデル・検索・送信にタイムアウトを設ける。
- 発言単位の claim と完成済み回答のキャッシュで再送時の重複生成を防ぐ。期限切れや応答喪失があるため、厳密な返信保証はしない。
- 既存の `ping` → `pong` はそのまま維持する。

## 制限

直近のテキストは索引を待たず参照するが、過去の検索索引や添付解析の反映前には根拠が見つからない場合がある。AI の OCR・説明・回答には誤りがあり得る。
既に LINE に送った回答を、元発言の取消に連動して取り消す機能はない。
