# ADR 0016: 1対1の履歴検索を実行で保証し、発言の前後も読む

- 日付: 2026-11-01
- 状態: 採用

## 背景

旅行に関連する発言は取り込み・索引化済みだったが、1対1のモデルが検索せず過去の未発見回答を再利用していた。実モデルで再現した。また、短い検索語だけでは質問文を検索した場合と候補が異なり、短文単位の索引では前後の旅程相談が欠けていた。

## 決定

- 回答を一般知識・直近記録・過去記録・未発見に分類する。過去記録・未発見の回答を検索前に返そうとした場合は、その回答を送らず、許可されたトークを最大3つ検索して回答を再生成する。既存の最大3回の推論・4回のツール予算と利用料金制限を維持する。
- 各トークの最初の検索は、本人の質問文とモデルが生成した検索語の両方を使う。後続の絞り込みはモデルの検索語だけを使う。質問自体を失う言い換えを避け、検索費用は既存の本人の枠に計上する。
- 各検索候補に最大12件の前後発言を加え、重複を除き、候補間で均等にコンテキスト枠を配分する。全体の最大80根拠・検索結果12KB・プロンプト26KBは維持する。全文取得も同じチャットと未取消発言に限定する。
- 検索後は無関係な直近会話と過去のbot回答をプロンプトから除き、今回の記録を優先する。過去bot回答の参照元が16件を超える場合は再利用せず、新たに調べる。本人の説明、旅行の計画、実際の訪問、発言日とニュースの発生日を区別する。
- モデルが開始・終了を同じ時刻にした不正な期間は、エラー応答にせず全期間検索に戻す。MCPクライアントが明示的に指定した不正な期間への入力検証は維持する。
- MCPにも `get_message_context` を公開する。チャットと発言IDの両方が一致した発言だけを起点に、取消済み・共有資料の投影を除いた前後を返す。同一時刻の複数発言はIDで順序を安定させる。

- 本文の年まで明記された日付をサーバー側で正規化し、最大8件の `mentioned_dates` と現在日（JST）に対する past / today / future を付ける。全角数字・令和/平成/昭和・元年・西暦表記を扱い、存在しない日付と年のない表現は推測しない。発言日時は別フィールドとして維持し、日付の意味（開催日かニュースの日か）は資料の本文から判断する。
- 1対1・グループ両方の回答に `current_time`（実際の回答時点）・`question_sent_at`・`timezone: Asia/Tokyo` を明示する。和暦・全角数字を解釈して開催日と比較し、過去の告知は「開催予定でした」と過去形で答える。実施記録があれば「開催されました」とし、予定日が過ぎたことだけで開催実績を断定しない。

## 確認

本番の旅行関連発言が ready であることと実際のVectorize検索結果を確認した。実モデルで検索省略を再現し、検索結果と前後発言を渡すと旭山動物園・十勝川温泉を回答に使用することを確認した。実際のLINEメッセージ送信によるテストは行わない。検索強制・前後取得・権限分離・取消・同時刻・検索語併用・不正期間の回帰テストを追加する。
