# ADR 0015: 履歴取り込みの進捗を状態別カウンタで表示する

- 日付: 2026-11-01
- 状態: 採用

## 決定

管理画面の「履歴インポート」に、現在参加中のトークの最新20ファイルについて確認済み件数、新規・重複件数、検索反映済み・処理待ち・予算待ち・失敗・対象外・取消の件数を表示する。自分以外が取り込んだファイルも参加者は確認できる。元の発言やアップロード者のIDは返さない。

キュー配送の数ではなく、取り込みファイルと論理ジョブの状態ごとに `history_import_counts` を保持する。既存データの初回集計後は、D1 のトリガーによりメッセージの作成・取消・削除とジョブの状態変更に追従する。元の更新とカウンタの変更が同じトランザクションで確定するため、並行更新や再配送で二重計上せず、処理がロールバックされたらカウンタも戻る。同じ表示区分内の retry / pending の変更などでは更新しない。ジョブ未作成の発言は処理待ちとして数える。

表示時とインポート継続処理の件数確認はカウンタだけを読み、メッセージやジョブの全件集計を行わない。状態ごとのカウンタ更新で書き込みは増えるが、表示の読み取り件数は発言数に比例しない。参加確認は既存の LINE API の権限確認を毎回利用する。初回表示・画面切り替え・手動更新時のみ取得し、定期ポーリングしない。

テスト用マイグレーションは公式の `readD1Migrations` で読み込み、トリガー内部の複数 SQL 文を分割しない。

D1 の SQL 互換性: [Cloudflare SQL statements](https://developers.cloudflare.com/d1/sql-api/sql-statements/)
